# Migrate from Ren'Py

The RenRS migrator is an offline source converter. It does not load Ren'Py, execute
Python, read `.rpyc` or Ren'Py saves, or promise identical behavior after conversion.

```sh
cargo run --bin renrs-migrate -- path/to/renpy/game migrated-game
cargo run --bin renrs-migrate -- --strict path/to/renpy/game migrated-game
```

Input may be a `.rpy` file or a project directory. The output directory must be
empty or missing. Directory migration recursively converts `.rpy`, copies ordinary
assets, ignores hidden directories, `cache`, `saves`, `tl`, and `.rpyc`, and always
writes `migration-report.json`. The report records source and output roots so editors
can reopen the original `.rpy` location.

## Automatic conversion

- Static `config.*`, `build.*`, and `preferences.*` values in `options.rpy` are
  classified. `config.name` and `build.name` become the title and stable project ID;
  supported default volumes go to the theme.
- Static strings, colors, numbers, booleans, and aliases in `gui.rpy` are parsed.
  Matching fonts, sizes, colors, and dialogue layout become `theme.json`; SDK-only
  fonts are not invented as project resources.
- A Ren'Py default `screens.rpy` is replaced by built-in RenRS screens and a generated
  `screens.json`. Extra custom screens remain explicit unsupported issues.
- Static `Character(...)` and static `image name = "path"` declarations that name an
  existing project resource.
- Static labels, including fixed parameters and defaults, narration, character dialogue,
  menu prompts, and unconditional basic menus.
- Static `scene`, `show ... at left/center/right`, `show ... as alias`, standard
  `onlayer`, integer `zorder`, and simple `hide`.
- Simple `$ variable = expression` and `default variable = expression`.
- `if`, `elif`, `else`, static `jump`, static `call` with positional/named arguments,
  and `return <expr>`.
- Static `loop`, `noloop`, `fadein`, and `volume` on `play music` / `queue music`, plus
  `play sound volume`, `voice`, `stop music fadeout`, and `pause`. Ren'Py's default
  music loop is emitted explicitly.
- A safe, parameter-free named transform subset is inlined at static `show ... at name`
  sites: standard `xalign`, bottom `yalign`, `alpha`, `zoom`, `rotate`, `xoffset`,
  `yoffset`, `linear`, and `ease`.
- `with fade` / `with dissolve` become `transition fade 0.5` under documented assumptions.
- Simple `[variable]` in dialogue becomes `{variable}`.

Scene and sprite names are matched against source image filenames. For example
`scene bg room` may match `images/bg_room.jpg` or `images/bg room.png`. If nothing
is found, an assumed path `images/bg_room.png` is generated and recorded as an
`assumption` in the report. A bare `scene black` is a deterministic exception: when
no matching source asset exists, the migrator generates a black `images/black.png`
without recording an assumption.

## Needs a human

- Python blocks, `init python`, ordinary `init`, and arbitrary Python expressions.
- Custom screen language, styles, displayables, and UI actions. Only the default
  template maps to the built-in UI.
- Parameterized or looping ATL, nonstandard alignment, dynamic image expressions, and
  custom transitions.
- Label `*args`, `**kwargs`, keyword-only parameters, dynamic jump/call, and parameter
  expressions outside the RenRS subset.
- Conditional/dynamic menus, complex Character, complex interpolation.
- Custom layers, `behind`, camera, video, and plugin statements. Declare custom
  targets manually with `layer name order integer`.
- Implicit fallthrough of Ren'Py labels; RenRS implicitly returns/ends at a label.

Unsupported source lines are kept as `# TODO migration:` comments and recorded as
`unsupported` in the report. They are not executed or silently dropped. Fixed label
parameters use Ren'Py-compatible call-time defaults and dynamic restoration on return.
Parameters on `start` and variadic parameters are still rejected. RenRS transforms
still need manual conversion.

## Report and strict mode

`migration-report.json` contains:

- `converted_files`: converted script count.
- `copied_resources`: copied ordinary asset count.
- `generated_resources`: deterministic assets generated by the migrator, such as a
  missing built-in black scene image.
- `version`, `source_root`, and `output_root`: report schema and migration locations.
- `generated_support_files` and `support_files`: generated theme/screen count plus each
  support file's status, mapped keys, and unmapped keys.
- `issues`: conversion issues with file, line, stable `code`, and
  `assumption` / `unsupported`.
- `summary`: issue totals grouped by kind, stable code, and source file.
- `post_validation_diagnostics`: diagnostics from re-parse, asset check, compile,
  and CFG analysis after conversion.

Default mode still writes the result and report when issues exist, so you can fix
them in steps. `--strict` still writes first, then fails if `issues` or post
validation diagnostics are non-empty. Use it in CI and batch migration checks.

## Recommended review

1. Migrate a copy into a new empty directory. Do not modify the original Ren'Py project.
2. Handle every `unsupported` and `assumption` in the report.
3. Add a stable `config id`, and give key dialogue and menus explicit translation IDs.
4. Run `renrs-fmt`, `renrs-check`, and `renrs-migrate --strict` side by side.
5. Accept every entry, menu branch, return path, and save/load point in the story.
6. Listen to audio separately. First-run music, sound, and voice defaults are `0.6`,
   `0.8`, and `1.0`; automated tests do not judge sound.

The repository's official `the_question` sample is a fixed migration baseline. It must
generate theme and screen files, reload and compile without post-validation diagnostics,
and keep the issue-code distribution from regressing accidentally.

The migrator only maps syntax that is provably safe. Full capability gaps are in
[Gap with Ren’Py](RENPY_GAP_ANALYSIS.md).
