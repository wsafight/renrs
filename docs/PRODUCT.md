# RenRS 产品文档

## 1. 产品定义

RenRS 是一套使用 Rust 独立实现、受 Ren'Py 启发的视觉小说引擎。它面向希望用声明式脚本组织
剧情，同时获得原生桌面发行、确定性运行、静态分析和可审计存档的创作者与开发者。

RenRS 使用自己的 `.rns` 语言，不执行 Python，不直接运行 `.rpy`，也不兼容 Ren'Py 存档。
离线迁移器只转换明确支持的静态子集，并将有歧义的内容写入报告。

## 2. 核心用户

- 制作视觉小说、互动叙事和对话原型的独立创作者。
- 需要无窗口检查、自动化发行和稳定数据格式的小型团队。
- 希望用 Rust 集成运行时或开发创作工具的工程团队。

## 3. 核心价值

- **低门槛创作**：用接近剧本的语法描述角色、对白、资源、变量和分支。
- **确定性运行**：脚本先解析、校验、编译和分析，不执行任意宿主语言代码。
- **可恢复状态**：执行、舞台、动画、音频、调用栈和回滚检查点都可序列化。
- **原生交付**：目录项目可一条命令构建为播放器加只读 `.renrs` 归档。
- **可诊断工具链**：检查、格式化、LSP、剧情图、本地化和迁移工具均可无窗口运行。

### 3.1 当前定位

RenRS 的差异化不是“使用 Rust 重写 Ren'Py”，而是把视觉小说开发变成可检查、可测试、
可复现的工程流程。对外应优先说明静态检查、路线测试、确定性状态和 Git 协作给创作者带来的
结果，而不是实现语言本身。

项目仍处于预发布阶段。功能已经实现表示代码、测试和文档落地，不表示经过长期真实作品验证，
也不表示能够低风险替代 Ren'Py。现阶段更准确的定位是：

> 面向技术型创作者和小型团队、支持剧情静态检查与自动化测试的 Git-friendly 视觉小说引擎。

### 3.2 当前适用边界

当前较适合愿意参与早期验证的技术型创作者、复杂分支实验项目，以及需要无窗口检查、路线回放
和可审计状态的团队。它暂不适合作为以下项目的低风险基础设施：

- 严重依赖 Ren'Py Python、插件、完整 Screen Language 或 ATL 的既有项目；
- 即将商业发行，并要求成熟商店、签名、公证和多平台支持的项目；
- 依赖 Live2D、复杂 shader、粒子、3D、平台服务或云存档的作品；
- 要求长期脚本和旧存档兼容，但不能承担预发布格式变更的长周期项目。

Launcher 和 VS Code 扩展已经提供创作入口，但非程序员创作者的首次安装、资源管理、即时预览、
教程和发行体验仍需要真实用户验证。

## 4. 当前用户流程

1. 使用 `renrs-init` 创建可玩的模板，再在一个或多个 `.rns` 文件中编写剧情，保持稳定的 `config id`。
2. 将图片、字体、音频、`theme.json`、可选 `screens.json` 和 `locales/*.json` 放入项目目录。
3. 使用 `renrs-check <project>` 完成脚本、资源和控制流检查。
4. 开发时用 `renrs <project-directory>` 运行，脚本、资源与支持文件变更可热重载；VS Code 扩展提供统一入口。
5. 使用 `renrs-i18n` 提取、更新和检查翻译目录。
6. 使用 `renrs-debug test/explore` 验证路线，再用 `renrs-build <project> <output-directory>` 生成发行目录。
7. 玩家设置、已读状态和存档写入系统用户数据目录，不污染项目或只读归档。

## 5. 已交付范围

### 5.1 脚本与静态分析

- `config title` / `config id`、`define`、`default` 和静态 `image` 声明。
- 背景、全局立绘 alias、可排序/清空的命名立绘层、对白、插值、基础富文本和条件菜单。
- `set`、确定性表达式、列表/记录及内置集合操作、`if` / `elif` / `else`。
- `jump`、带位置/命名/默认参数的 `call`、`return <expr>` 和 `_return`。
- `move`、transform、easing、串行/并行时间线、fade/dissolve 和角色预合成工具。
- 音乐、音效、语音、音乐队列、淡入淡出和静态 music/sound 相对音量。
- 多文件声明检查、资源检查、不可达代码、确定赋值和即时循环诊断。

### 5.2 播放与界面

- 1280x720 逻辑画布、等比缩放、背景/立绘/界面分层。
- 稳定排版的打字机文字、长对白分页、完整历史滚动、菜单焦点、自动播放、跳过已读和交互点回滚。
- 标题、设置、60 个手动存档槽、快速存读档，以及手动/快速/自动存档分组浏览。
- `theme.json`、项目字体、高对比度与减少动画设置。
- 桌面/Web `screens.json` 定制标题、对白、选项、存读档、偏好和历史，支持受控变量更新及只读 HUD。
- NVL、多段阅读、注音、下划线与系统自助朗读。
- 音乐、音效、语音独立音量，默认分别为 `0.6`、`0.8`、`1.0`；music/sound 语句可设置相对增益，测试模式静音。
- 目录模式监听脚本、媒体、主题、字体、翻译和界面；归档模式保持只读和确定性。

### 5.3 本地化

- 对白与菜单使用独立 `TranslationId`，支持显式 `@id`、菜单 `id` 和旧 ID alias。
- JSON 单语言 catalog，支持显式 fallback 和 `zh-Hans-CN -> zh-Hans -> zh` 逐级回退。
- 缺失或空翻译回退源文本；翻译发生在变量插值和富文本解析之前。
- 播放器读取 `locales/*.json`；语言来自玩家设置，或首次使用 `RENRS_LANGUAGE`。
- 设置页可即时切换当前对白/菜单的语言，失败时保留原状态；显式选源文本后不再被环境变量覆盖。
- `renrs-i18n extract/update/check` 支持提取、新增空项、保留 obsolete 项和 CI 完整性检查。

### 5.4 项目与发行

- `ProjectSource` 对目录和 `.renrs` 提供一致的脚本与资源 API。
- `.renrs` 使用版本化清单、规范相对路径、边界检查和逐资源 SHA-256。
- 播放器可直接打开 `.renrs`；无参数时优先打开播放器相邻的 `game.renrs`，不依赖工作目录。
- `renrs-build` 校验项目并输出播放器、`game.renrs`、构建清单、运行说明及引擎/字体许可证。
- 本地发行脚本组装当前平台工具包、Web shell、编辑器扩展和带校验值的 SDK。

### 5.5 当前版本存档

- 项目尚未上线，允许破坏性格式变更，不迁移旧容器或旧快照格式。
- 当前运行时快照格式为 v7。相同脚本指纹直接恢复；内容更新后仅映射显式 `@id`/`alias`，
  自动位置、被删除的位置或不一致的调用栈会明确拒绝，不猜测执行位置。
- v7 记录稳定执行位置、调用点返回地址、共享变量节点、舞台、transform、带相对音量的音频队列、语言、历史和有界回滚检查点。
- 当前存档容器为 v2，包含引擎版本、项目 ID、内容指纹、游玩时长、章节和 SHA-256 完整性校验；
  拒绝其他容器版本，以及缺失或不匹配的校验和。
- 损坏槽位在列表中可见；仓储 API 支持导入/导出，播放器轮换 3 份 quick 和 5 份 auto。
- 已读状态不属于单个快照，独立保存在项目级 `read.json`。
- 热重载和当前格式的持久化存档共用 ID/alias 映射；失败时分别保留当前会话或原存档。

### 5.6 工程约束

- 核心运行时不依赖窗口，可进行无 GPU、无音频设备测试。
- parser、compiler、analysis、runtime、player、migration 和 LSP 按职责拆分。
- 测试会拒绝根包和所有 workspace crates 中超过 500 行的 Rust 源码文件。
- 视频通过 FFmpeg/FFprobe 转为帧或流式清单，可配套 WAV 音轨并按音频时钟播放。

本轮增加的异步存档、成就、Web、调试器和发行工具范围见 [新增能力](UPGRADES.md)。

### 5.7 创作与规模验证

- `renrs-init` 创建有插图、中文翻译、双结局、主题及路线断言的项目。
- VS Code 扩展提供 LSP、保存时项目诊断、图片/音频预览、运行、发行构建与路线测试。
- `renrs-debug` 提供状态查看、交互录制、重放、路线断言和有界分支探索，截断时明确报告。
- 后台图片解码、少量后续图片预测、纹理/音频缓存预算、存档列表缓存、流式归档打包。
- `renrs-bench` 生成多文件合成项目并测量编译、运行、快照、存档、监听和归档操作。
- 播放器 `--smoke-test` 在独立数据目录中驱动真实渲染和存读档，输出 PNG 和 JSON 报告。

## 6. 数据位置

`config id` 是持久化身份。建议使用稳定的反向域名，例如 `org.example.my-story`，发布后不要修改。

- macOS：`~/Library/Application Support/RenRS/<project-id>/`
- Windows：`%APPDATA%/RenRS/<project-id>/`，缺失时回退 `%LOCALAPPDATA%`
- Linux：`$XDG_DATA_HOME/renrs/<project-id>/`，未设置时使用 `~/.local/share/renrs/<project-id>/`

目录包含 `settings.json`、`read.json` 和 `saves/*.json`。未声明 `config id` 时会从标题派生，适合原型，
不适合作为已经发行项目的长期身份。

## 7. 当前非目标

- Python、任意宿主代码、Ren'Py 插件或 Ren'Py 存档兼容。
- Ren'Py screen language、完整 style/displayable 系统和完整 ATL；只提供受限 JSON 界面子集。
- Live2D、复杂粒子、3D、自定义 shader、layer camera 和任意 displayable。
- 原生 Rust 移动渲染、云存档、联机和网络自动更新；当前移动输出使用 Capacitor WebView。
- 自动获取发行凭据或代替发行方完成商店审批；现有签名、公证和移动打包工具需对应 SDK 与账号。
- 稳定原生插件 ABI；未来若需要扩展，优先评估最小权限 WASM。

## 8. 验收标准

- 同一项目从目录和归档加载得到一致脚本与资源，并可通过无窗口检查。
- 双路径示例可完整运行；存读档、回滚、热重载和翻译不破坏稳定执行位置。
- 无效语法、资源、控制流、归档、翻译目录和存档校验均返回明确错误。
- P0/P1 本地门禁通过；目标桌面平台发行前分别完成本机或虚拟机验收，严格 Clippy 无警告，
  Rust 文件不超过 500 行。
- 音频状态通过自动测试，测试模式静音；实际听感留给最后人工验收。

### 9.1 产品化优先级

1. **真实作品闭环**：由项目所有者或外部创作者使用一部 30 至 60 分钟、包含多结局、存读档、
   本地化、音视频和自定义界面的作品验证完整流程，并记录开发耗时、构建结果和平台问题。
   商业项目、公开发行和外部跨平台验收不属于当前本地开发范围，不能用合成夹具代替。
2. **降低首次使用门槛**：Launcher、SDK 组装与本地端到端验收已经完成；下一步是按平台提供可下载
   的构建、减少宿主依赖，并完成签名、公证及安装体验验证。
3. **把核心优势产品化**：在 Launcher 或编辑器中直观呈现文件位置、未覆盖路线、不可达结局和
   本地化遗漏。提交前后路线影响分析尚未实现，不能作为当前能力宣传。
4. **建立稳定窗口**：候选版本应明确脚本、结构化协议和存档格式的兼容范围，提供升级说明，并以
   文档工作流及带版本记录的本地完整验收作为发布证据。
5. **控制功能范围**：真实作品提出需求前，不优先投入 Live2D、3D、复杂 shader、云端账户、构建农场
   或大型在线 Dashboard。

### 9.2 Agent 协作方向

确定性运行时、无窗口检查、剧情图和路线测试适合被 Agent 调用，但 Agent 能力是创作工具链的扩展，
不能代替基础创作体验、引擎可靠性或真实作品验证。产品定位仍以视觉小说引擎为主，目标是让 Agent
成为可验证的技术制作助手，而不是用自动生成故事作为引擎卖点。

当前机器接口基础包括 `renrs-check --json`、输出结构化结果的
`renrs-debug inspect/test/explore`、JSON 验收报告 `renrs-accept`，以及 Web engine 的 `inspect()`。
下一阶段应在这些现有二进制上统一退出码、错误码和带版本号的 JSON Schema；是否合并为单一
`renrs <subcommand>` 不是前置条件。未实现的目标命令或接口必须标注为提案。

职责边界如下：

- Agent 负责理解用户意图、提出修改计划和编辑文件；
- RenRS 负责返回项目真实状态，并对明确的项目版本、候选补丁或 Git diff 执行影响分析；
- 检查、路线测试、截图和构建必须复用核心库或稳定 CLI，不能在编辑器、MCP 中形成不同语义；
- 修改类接口必须限定目标文件、返回可审查差异，并保留用户审批边界。

理想闭环是“读取真实状态 -> 计划与编辑 -> 静态检查 -> 路线测试 -> 截图与覆盖报告 -> 用户审阅
-> 构建”。实现顺序和能力边界见 [路线图](ROADMAP.md#agent-协作路线提案)。
