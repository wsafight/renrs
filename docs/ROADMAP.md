# RenRS 路线图

本页保留早期优先级和里程碑，适合了解规划背景，不作为新手入口或当前进度清单。开始使用请读
[快速开始](QUICKSTART.md)，当前完成、暂缓与延期范围见 [当前开发进度](NEXT_PRODUCT_WORK.md)，
历次交付细节见 [产品优化记录](PRODUCT_UPGRADES.md)。

项目尚未上线；`0.1.0-rc.1` 起冻结 v1 机器协议、归档和界面契约。RC 之前的旧版本兼容和
存档迁移不在当前范围，具体策略见 [发布契约](RELEASE.md)。

## 优先级定义

- **P0**：影响项目能否可靠创作、运行、保存和发行的阻塞项。
- **P1**：影响中型视觉小说生产效率、表现力和迁移质量的重要能力。
- **P2**：需要独立设计或引入较重依赖的扩展，不作为当前版本完成条件。

完成表示代码、无窗口测试和文档均已落地，不表示与 Ren'Py 全量功能等价。对比基于
`references/renpy` 的 `9ed7dd3`（2026-09-04），详细矩阵见
[Ren'Py 差距分析](RENPY_GAP_ANALYSIS.md)。

## P0：可靠创作与发行（已完成）

- [x] 统一 `ProjectSource`：目录项目和 `.renrs` 归档使用相同的脚本、图片、字体、主题、翻译和音频读取边界。
- [x] `.renrs` 可直接检查和播放；归档模式禁用热重载，目录模式保留事务式热重载。
- [x] 增加 `config id`，并将设置、已读状态和存档放入按项目 ID 隔离的系统用户数据目录。
- [x] 增加 `default`、静态 `image`、标签参数、`call` 参数、`return <expr>` 和 `_return`。
- [x] 增加条件菜单，修复跨 `call` / `return` 边的确定赋值分析。
- [x] 将执行 ID、翻译 ID 和已读 ID 分离；支持 `@id` 与旧 ID `alias`。
- [x] 实现 JSON 翻译目录、显式及语言标签回退、空翻译回退源文本，并在插值和富文本解析前翻译。
- [x] 存档仅接受当前快照格式 v7 和当前脚本指纹；开发热重载保留稳定 ID 映射。
- [x] 存档包含项目 ID、内容指纹、游玩时长和章节，使用 SHA-256 完整性校验；损坏槽位保持可见。
- [x] 存档容器只读写 v2，强制校验和；归档解包拒绝符号链接穿越和覆盖。
- [x] 增加 3 份快速存档和 5 份自动存档轮换，以及导入/导出仓储 API。
- [x] 增加 `renrs-build`，生成播放器、`game.renrs`、构建清单和运行说明组成的发行目录。
- [x] 增加 `renrs-migrate --strict`，迁移后再次执行解析、校验、编译和控制流分析。

## P1：生产效率与表现力（已完成）

- [x] 增加可保存、读档和回滚的通用 `transform`：x/y、缩放、旋转、透明度、锚点、裁剪和取消裁剪。
- [x] transform 支持 `over` 以及 `linear`、`in`、`out`、`in_out` easing；保留基础位置 tween 和淡入转场。
- [x] 音乐、音效和语音保持独立通道；增加音乐 fade-in、队列、fade-out 和静态 music/sound 相对音量。
- [x] 使用 WAV/Ogg 时长推进非循环音乐队列；当前默认音量为 0.6/0.8/1.0，测试静音。
- [x] 增加项目 `theme.json`、自定义字体、高对比度和减少动画配置。
- [x] 增加 `renrs-i18n extract/update/check` 本地化工作流；播放器从 `locales/*.json` 读取目录。
- [x] LSP 增加工作区符号、定义、引用、重命名和补全，并保留诊断和格式化。
- [x] 离线迁移器覆盖明确支持的 Ren'Py 静态子集；不确定或动态语法进入结构化报告，不静默猜测。
- [x] 解析器、运行时、编译器、分析器、迁移器、播放器和 LSP 按职责拆分。
- [x] 用测试强制 `src/` 和 `tests/` 下每个 Rust 文件不超过 500 行。
- [x] 拆分 core/Web/媒体/编辑器/release 本地门禁，补齐 Launcher 协议与 Web 语义边界测试。
- [x] 建立 10 章、500 条对白、两条路线的 30–60 分钟第一方参考 fixture；外部作者作品仍待验收。
- [x] 原生文字换行使用 shaped cluster 边界；Web 提供稳定对话 live status 和场景、选项、控件语义。
- [x] Ren'Py 迁移覆盖静态 `easein`/`easeout`、ATL pause 与 master camera；动态、循环和 layer camera 明确报告。
- [x] 冻结发布格式矩阵并准备 `0.1.0-rc.1`，本地移动 wrapper 纳入 release 门禁。

## P2：剩余扩展

本轮已先交付 P2 中可独立验证的性能、界面子集和创作工具，详见 [顺序优化验收](OPTIMIZATION.md)：
后台图片解码与预测、资源预算、存档列表缓存、流式打包、模板及编辑器入口、剧情路线调试、
声明式 JSON 界面、合成基准与原生截图。以下条目描述剩余扩展，不重复将已交付子集列为未实现。

以下是与 Ren'Py 相比仍明显缺失的能力。它们不能在没有真实后端时标记为支持。

1. **自定义界面扩展**：已有嵌套 viewport、drag/drop 和 Web 语义；任意 displayable 与原生 OS 辅助技术树仍缺失。
2. **高级文本排版**：现有 `rustybuzz` shaping、BiDi、字体回退、CJK 换行和 ruby 基础上，补齐
   shaped cluster 感知换行已交付；竖排、彩色 emoji 和原生屏幕阅读器语义仍缺失。
3. **高级表现**：命名立绘层已交付；完整 ATL、layer camera、任意 displayable、组合转场、shader、粒子和 Live2D 仍缺失。
4. **视频**：本地化音轨、相对音量和字幕轨已交付；更多真机和长片的同步验收仍待完成。
5. **性能**：真实项目样本和字体缓存预算；增量编译已交付。执行层已有线性 `Program` 指令 IR，
   只有 profiling 证明表达式求值或指令分派是瓶颈时，才评估紧凑 opcode 或表达式 bytecode。
6. **发行平台**：原生 Rust 移动渲染、Capacitor 真机矩阵、签名/公证外部验收、商店 SDK 和网络自动更新客户端。
7. **高级叙事状态**：固定回滚、更细粒度偏好同步和云存档。
8. **迁移覆盖**：默认 screen、常用静态 ATL/master camera 和第一方参考基线已交付；复杂 image expression、
   参数化/循环 ATL、动态 jump/call、自定义语句和更广的真实项目样本库仍缺失。
9. **扩展机制**：不嵌入 Python；如确有需求，单独评估最小权限的 WASM 插件 API。

## 推荐实施顺序

1. 第一方 30 至 60 分钟参考 fixture 已用于回归；下一步仍需用外部作者的真实中型作品建立创作、
   迁移和发行基线，记录帧耗时、资源峰值、存档读写、制作耗时和平台问题。
2. 按真实作品的阻塞项补高级文本排版、JSON 界面控件、可访问性、ATL 和迁移覆盖；每项都要求
   桌面/Web 共用语义、结构化诊断和回退策略。
3. 持续维护已完成的 Web 工具链类型化：Web 播放器、VS Code 扩展和 Launcher 视图均使用 strict
   TypeScript；WASM 边界使用显式解析器，Launcher 机器协议使用 Zod 校验。稳定的 Node 运维脚本
   保留 `.mjs`/`.cjs`，由 Biome 统一格式化。
4. 用真实视频和长片验证现有 FFmpeg/Rodio/HTML 媒体时钟，并完成桌面、浏览器和 Capacitor 真机矩阵。
5. `.rns`、机器协议、界面 schema、归档和存档兼容窗口已定义并准备 `0.1.0-rc.1`；完成外部作品、
   目标平台与发布凭据门禁后再发布 `0.1.0`。
6. 只有真实基准显示执行 IR 是可感知瓶颈时，才优化表达式 IR 或引入 bytecode；不得将完整 VM
   重写预设为播放器性能地基。

## 技术演进边界

- **执行模型**：编译器已经将脚本降低为带稳定 ID 和跳转目标的线性 `Program` 指令；runtime 按
  instruction cursor 执行。当前递归执行的是指令内表达式，不应再将整体描述为 tree-walking。
- **文本系统**：继续复用现有 `rustybuzz`、BiDi、Unicode segmentation 和字体缓存。引入
  `cosmic-text` 等重依赖前，应以复杂文字、ruby、竖排、内存和跨平台渲染基准做隔离比较。
- **存储边界**：现有存档继续使用临时文件、`fsync`、原子替换、版本和校验和。mini KV、WAL 或
  LSM-tree 适合作为独立系统编程实验；在云同步或大量增量状态出现前不纳入 RenRS 主路径。
- **Ren'Py 差距**：不追求逐项复刻。Python 生态、Ren'Py 存档和任意宿主代码保持非目标；只补真实
  作品证明会影响创作、表现、迁移或发行的能力。
- **TypeScript 与 Web**：`web/src` 已在 Vite 下使用 strict TypeScript，并为 WASM/JSON 边界提供
  显式类型和运行时校验；VS Code 扩展由 strict TypeScript 编译为发行用 CommonJS bundle；Launcher
  视图由 Vite 构建，并用 Zod 校验 API schema。Astro 文档站保留现有 TypeScript 支持，短小且稳定的
  `.mjs`/`.cjs` 构建、发行和测试脚本不因扩展名统一而强制迁移。Biome 负责这些维护源码的统一格式化
  和静态检查。
- **框架选择**：Vite、Astro、Playwright 和 Capacitor 已覆盖现有构建与平台边界。Web 播放器以游戏
  舞台和 WASM 状态机为核心，暂不引入通用 SPA 框架；只有组件生命周期和状态同步复杂度在真实项目中
  持续造成缺陷时，再用独立原型比较 Lit 或 Svelte 的包体、可访问性、测试和移动端行为。

## Agent 协作路线（提案）

状态：暂缓。当前不实现 `SKILL.md`、`llms.txt`、只读 MCP Server 或其他 Agent 集成；
以下内容仅保留为未来提案，不属于本轮 P1/P2 完成范围。

这条路线基于现有静态检查、确定性运行时、无窗口调试和路线测试，不表示下列能力已经实现。
Agent 层应复用核心库或稳定 CLI；引擎负责提供事实和验证候选变更，Agent 负责计划与编辑。

1. [x] 统一现有二进制的退出码、错误码和带版本号的 JSON Schema。`renrs-check --json`、
   `renrs-debug inspect/test/explore`、`renrs-accept` 和 Web `inspect()` 是现有基础。
2. [x] 增加只读项目状态接口，覆盖配置、角色、变量、资源、剧情图、本地化、脚本指纹和能力版本。
3. [x] 接受明确的基线与候选项目或 Git revision，报告受影响路线、结局、翻译和存档结构；不要让引擎
   在没有变更输入时猜测 Agent 的计划。
4. 发布 `SKILL.md`、`llms.txt`、JSON Schema 和机器接口版本策略，明确修改步骤及必跑检查。
5. [x] Launcher 展示检查、变量、路线测试、覆盖、本地化、迁移与影响报告，并提供项目截图预览。
6. 在接口稳定后提供只读与验证优先的薄层 MCP Server，修改操作必须返回目标文件和差异。
7. 由项目所有者或外部创作者用一部真实作品验证人类与 Agent 协作流程；该外部验收不属于当前
   本地开发范围。

云端账户、在线素材存储、复杂团队权限、托管构建、模型网关、计费系统和大型 Dashboard 不属于
这条路线的近期范围。Agent 接口也不能代替非程序员创作体验、基础产品质量或真实作品验证。

## 历史里程碑

- **v0.1**：脚本 AST、校验、解释器、基础舞台、音频前端、设置、存档和示例。
- **v0.2**：多文件项目、稳定 ID、控制流分析和事务式热重载。
- **v0.3**：回滚、自动播放、跳过已读和独立语音通道。
- **v0.4**：淡入、位置 tween、整数 layer 和基础富文本。
- **v0.5**：格式化、LSP、剧情图、资源归档和三平台发布模板。
- **v0.6**：Ren'Py 静态子集迁移和结构化兼容性报告。

## 取舍记录

- 使用相近但独立的 `.rns` 语法，不承诺直接执行 `.rpy` 或兼容 Ren'Py 存档。
- 核心运行时不执行 Python 或任意宿主代码，保持确定性、可分析和可无窗口测试。
- 执行位置使用稳定指令 ID；翻译和已读状态使用各自独立的身份边界。
- 目录用于创作和热重载，校验过的 `.renrs` 用于只读发行。
- 音频人工试听留到最后验收；自动验证只检查状态机、格式和队列推进。
